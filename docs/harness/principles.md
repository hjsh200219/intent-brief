# 하네스 원칙

에이전트가 이 repo 를 추론할 수 있게 하는 원칙과 채점 기준. `/sh:harness-gc` 가 이 기준으로 P1~P12 를 채점한다.

## 원칙

- **지도이지 안내서가 아니다**: AGENTS.md 는 정본으로 가는 링크와 불변 조건만 둔다(120줄 이하). 상세는 하위 문서 하나에만 쓴다.
- **증거 우선**: 동작 주장에는 테스트·명령·파일 경로를 붙인다. 숫자에는 센 방법을 붙인다.
- **회의적 평가**: 완료 주장은 새 증거가 나오기 전까지 미흡으로 본다. 검증자는 작성자와 다른 문맥에서 돈다.
- **하네스 단순화**: 하네스 구성은 모델 능력에 대한 가정이다. GC 3회마다 쓸모없는 검사·문서를 걷어 낸다.
- **단계 독립**: 단계마다 입력·출력 파일을 두고 문맥을 새로 시작한다(압축보다 초기화).
- **스프린트 계약**: 위험이 있는 정리는 수정 전에 기대 효과를 먼저 적는다.
- **채점 앵커**: 점수는 취향이 아니라 아래 앵커의 관측 사실로 준다.
- **비밀 절제**: 토큰·실제 의뢰인 자료는 문서·로그·픽스처에 남기지 않는다(공개 repo).

## 12원칙 채점 (0–10)

P1 진입점 · P2 지도 · P3 불변식 강제 · P4 관례 · P5 단계적 공개 · P6 레이어+테스트 커버리지 · P7 GC 자동화 · P8 관측성 · P9 repo 안의 지식 · P10 재현성 · P11 모듈성 · P12 자기 문서화

| 점수 | 앵커 |
|---|---|
| 0–2 | 없음 또는 낡음 |
| 3–4 | 부분적·수동 |
| 5–6 | 쓸 수 있으나 알려진 빈틈 |
| 7–8 | 일관되게 검사됨(도구가 실패시킨다) |
| 9–10 | 측정되고 강제되며 추세가 기록됨 |

테스트 개수는 커버리지의 증거가 아니다. CI 는 두지 않는다(2026-10-14 사용자 결정) — 강제는 로컬 pytest·validate 로만 한다.
